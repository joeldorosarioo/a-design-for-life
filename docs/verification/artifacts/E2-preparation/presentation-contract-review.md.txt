## Achados

### [P2 — corrigido e fechado] Criar arrays novos para cada default de perfil legado

Arquivo: `E:/a-design-for-life/src/features/professional-profile/contracts/profile-dto.schema.ts:70` e `:75`.

Os defaults de `homeAbout` e `approach` passam objetos constantes com arrays aninhados para `.default(...)`. A versão instalada do Zod aplica somente `util.shallowClone(defaultValue)` (`node_modules/zod/v4/classic/schemas.js:1282–1288`); o clone de objeto usa spread (`v4/core/util.js:255–259`) e o parser devolve esse default sem percorrer o schema interno (`v4/core/schemas.js:2166–2175`). Assim, dois parses de snapshots legados sem esses grupos recebem a mesma referência de `trajectory`/`methods`. Um consumidor que acrescente um item ao primeiro DTO contamina o default de leituras posteriores. O resultado deixa de representar os arrays vazios do snapshot confirmado e pode inserir conteúdo que não veio daquela geração.

Correção mínima: usar funções em ambos os defaults, criando os arrays no corpo de cada função. Acrescentar regressão que faça dois parses legados, altere os arrays do primeiro e comprove que o segundo permanece vazio. Este comportamento foi confirmado por leitura da implementação instalada, sem executar teste; o coordenador foi informado e ficou responsável pelo RED/GREEN e pela edição.

Re-review: relidos os arquivos efetivos após a correção. Os dois defaults agora usam funções com arrays novos; os dois testes novos fazem um parse legado, inserem um item no array resultante e exigem array vazio no parse seguinte. Lido o log `.work/E2.2-profile-default-isolation-red.txt`: as duas regressões falharam pelo vazamento esperado (2 falhas, 9 passes). Lido `.work/E2.2-profile-navigation-refactor.txt`: 78/78 testes passaram em sete arquivos. São execuções do coordenador verificadas pelos registros, não testes executados por esta revisão. O P2 está fechado, sem novo achado no fix.
