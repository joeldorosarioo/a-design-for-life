As duas primeiras tentativas de PUT receberam HTTP422 porque o schema da API rejeita contexts e checks simultaneamente (oneOf). O payload foi corrigido para usar somente checks com app_id, sem enfraquecer a política; o PUT seguinte e o GET de confirmação passaram. Isso é falha de configuração, não RED comportamental do portfólio. A rejeição GH006 posterior é o resultado esperado do teste de controle de acesso, não bloqueio de execução.
