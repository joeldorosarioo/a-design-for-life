### S1 [P2] Validate the optional profile sharing image before publication

**Location:** `src/features/professional-profile/content/validate-publication.ts:43–45` (and the callback's final return at line 69).

**Trigger:** publish an otherwise complete profile with `seo.image = { media: <existing image ID>, decorative: false, alt: '' }`, or with a decorative sharing image and a nonempty alternative. The input is accepted by `profileInputSchema` / `imageUseInputSchema`. The publication guard checks only `home.portrait` and the three `about` image uses; it never checks `seo.image`. The collection exposes that sharing image using the same `imageUseField`, including its per-locale alternative/classification, at `professional-profiles.ts:226`.

**Impact:** a normal native or direct API publication can persist an image use that violates the approved image-alternative rule, without a field-specific publication error. This is an E1.4 metadata-validation omission, separate from the intentionally deferred E1.6 byte/upload validation. Spec §4.2 states: “Imagens informativas exigem texto alternativo” and requires decorative classification with an appropriate empty alternative. The contracts also place alternatives on each editorial image use. There is no implemented or documented derivation for the selected profile sharing image that supplies the missing validation. The equivalent optional case sharing image is already checked in `cases/content/hooks/validate-publication.ts:59`.

**Minimal fix:** when `seo.image.media` is selected, call `requireImage(errors, seo.image, 'seo.image')`; keep the sharing image optional. Add a real isolated Payload/PostgreSQL regression proving missing informative alt and nonempty decorative alt reject publication at `seo.image.alt`, preserve the old published version/revision, and still allow an incomplete draft.

**Evidence status:** confirmed by tracing the collection, input schema, helper and complete publication callback. No new test or database was run by this reviewer; the coordinator was notified so a focused real-PG RED/GREEN can be run under the existing isolated lifecycle.
