## Mudança

`classify-missing-public-media.ts` extrai, sem alterar a regra A1, a classificação que existia dentro de `resolveMediaAccess`. Os dois caminhos agora usam essa mesma capacidade interna:

```ts
classifyMissingPublicMedia(mediaId, capturedRoot: PublicRoot | null, req?): Promise<404 | 503>
```

O helper usa uma requisição Native fresca para ler somente metadados/usos. Um uso SQL `confirmed` cujo proprietário não está coberto na raiz recebida produz503; um proprietário coberto com `media: []` produz404, inclusive com ACK SQL antigo. Mídia privada/nunca publicada e ID desconhecido saudáveis continuam indistinguíveis como404. Erros da classificação sobem aos dois chamadores, que retornam503 vazio sem cache. SQL nunca devolve bytes, manifesto autorizado ou permissão de passagem para Next.

A raiz é o argumento capturado pelo chamador, sem nova leitura de `current.json` no classificador. `resolveMediaAccess` conserva prévias, variantes, leitura de objeto e status anteriores. `handleNextImage` separa `!manifest` (classificação) de PDF/outro manifesto positivamente recusado (404). Raiz ausente também é classificada conforme A1; raiz ilegível/corrompida continua503. O caminho positivo com manifesto confirmado não consulta Native. A importação de `createLocalReq`/Payload ocorre apenas dentro do classificador, depois de obter o provider; o caminho público conhecido não carrega essa dependência para classificar.

Nenhuma mudança de API pública `handleNextImage`, app/proxy, configuração Next, ambiente, dependências, lock, commit ou banco foi feita por este agente. Os testes PostgreSQL foram executados pelo agente que detinha exclusivamente55433, sem concorrência com outro lifecycle.

## O que os novos casos Native provam

- Publicação real confirma uso SQL. Remover o proprietário da raiz ou manter proprietário sem campo de cobertura `media` faz as entradas original e otimizador retornarem503. O otimizador é exercitado tanto em chamada externa quanto em chamada interna HMAC válida.
- Retirada real produz cobertura `media: []`. Recolocar deliberadamente os usos SQL confirmados anteriores pelo adaptador Native — fixture de ACK antigo — não concede bytes e mantém404 nas duas entradas.
- Classificação direta com raiz capturada coberta mantém404 quando o arquivo atual é posteriormente trocado por raiz sem proprietário; classificação com raiz capturada sem proprietário mantém503 depois de restaurar no disco a cobertura. Isso demonstra ausência de seleção de raiz nova pelo classificador.
- Upload privado real e UUID inexistente recebem o mesmo404 saudável. Nenhum fetch do otimizador deveria ocorrer nesses casos: a origem interna é um loopback sem serviço e o resultado503 distinguiria uma tentativa indevida de fetch.

Nenhum classifier callback foi simulado. Os testes unitários de origem indisponível usam um provider que falha para demonstrar503; eles não alegam404 de retirada ou privacidade saudável sem Native real. Os dois casos unitários antigos que usavam somente root passaram a esperar503 quando a classificação Native não pode executar; sua alegação anterior de404 foi substituída pelos casos PostgreSQL acima, após RED Native comprovado.
