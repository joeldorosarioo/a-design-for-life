## Riscos nomeados e limites

1. **FS e SQL distintos:** o intervalo raiz→ACK é recuperável; não há commit distribuído de dois recursos. Intenção SQL pendente não é geração pública confirmada.
2. **Compatibilidade do adapter:** a observação de COMMIT caracteriza Payload 3.92.1 e @payloadcms/db-postgres 3.92.1 com drizzle-orm 0.45.2; atualização exige repetir os testes reais de falha/concor­rência.
3. **Persistência e topologia:** exclusividade entre processos no mesmo host/diretório; múltiplos hosts e volumes de produção exigem desenho e prova da etapa3. Durabilidade contra queda de energia Windows não foi comprovada.
4. **Processo HTTP de falha:** reinício/PG indisponível são provados por processo HTTP separado com funções de produção, além dos E2E Next; não se apresenta esse harness como servidor Next reiniciado.
5. **Migração:** dados legados elegíveis exigem editor existente e bootstrap antes de novas mutações. Nenhuma conta fictícia de produção é criada.
6. **Conteúdo:** fixtures, pessoas, métricas e bytes de teste são sintéticos; Figma demonstra modelo em draft. Conteúdo final e fornecedores reais continuam fora desta etapa.
